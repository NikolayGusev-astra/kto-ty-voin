# История изменений kto-ty-voin


- v1.0.0 - 23.10.2026: создание. Опрос, карта болей, подбор, отчёт, демо.
- v1.1.0 - 23.10.2026: по итогам трёхагентного прогона (учительница): граница пользователя проверяется против самого агента (где исполняется модель); sanitize-поток при запрете «данные наружу» - только условная опция; статус «уже есть» только после прогона; у каждой рекомендации - чем проверена; запрет внешних фактов без прогона; запрет рекомендаций из собственной среды агента (корпоративный MCP, личные скиллы); канон чужого окружения - `hermes skills list` профиля пользователя плюс Hub-поиск; явный статус «работа не завершена» без согласованного демо.
- v1.2.0 - 23.10.2026: по итогам обсуждения «любой человек, любая цель»: цель «научиться новому» как равноправный профиль (цепочка инструмент-язык-ресурсы-модель-тренер); ПДн и юрисдикция - не стоп-кран, а шкала «запрет → информированный выбор → рекомендация» с картой «куда что уходит» и RU-доверенными провайдерами из живого каталога; ноль предположений об аккаунтах, карте, почте и установленном ПО.
- v1.3.0 - 23.10.2026: по итогам чистотного прогона на Викторе (цель Java, ноль аккаунтов, без регистраций): провенанс - точная команда этого сеанса и её результат; веб-поиск не равен «живому заходу»; множественное число - только для реально открытых скиллов; источник локальной модели проверяется включая «нужен ли аккаунт»; community-скилл без security scan - «есть в каталоге, не проверено»; фантазированный провенанс бракует отчёт целиком; в отчёте для не-инженера запрещены и кальки.
- v1.3.1 - 23.10.2026: по итогам батча чистотных прогонов (швея, бухгалтер, фермер): режим «Hermes не устанавливается на машину пользователя» (старая ОС/Python не проходит): агент продолжает отвечать из своего окружения и ведёт человека вручную - ручной путь сейчас + план на будущее, без платных обновлений ОС и без молчания о несовместимости.
- v1.4.0 - 23.10.2026: по итогам трёх параллельных чистотных прогонов (швея, бухгалтер с ПДн третьих лиц, фермер на Win7): витрина загрузок ≠ release-notes (блокирующая находка: рекомендованная ветка уже ушла в архив); редирект-цепочка цитируется как есть; встроенные возможности агента - под тем же правилом «уже есть после прогона»; inspect-карточка без SKILL.md - не рекомендация; бесплатность - через страницу Pricing; отказ по границе - только проверенная часть факта; ноль домысла о данных пользователя; провенанс без служебных профилей.
- v1.4.1 - 23.10.2026: рефакторинг после пяти прогонов: правила провенанса вынесены из п.3 в references/provenance.md (п.3 разбух до нечитаемой стены), история изменений упорядочена.
- v1.5.0 - 23.10.2026: по обратной связи владельца: вопрос «какая у тебя цель» воспроизводит ошибку гайдов - пользователь не знает ни целей, ни возможностей агента. Инвертировано: опрос - только факты жизни, цель из раундов изъята; новая ступень «витрина возможностей» - 3-5 классов возможностей сценами на его ответах, распознавание вместо генерации; цель формулирует агент на подтверждение; микро-демо во время интервью как опция; отклик витрины задаёт приоритет подбора. Возможности агента слиты в витрину (бывший п.4).
- v1.5.1 - 23.10.2026: по обратной связи владельца: убран хардкод пути проекта владельца из п.5 - скилл отдаётся другим агентам и не должен раскрывать чужое окружение; путь отчёта - из соглашений пользователя.
- v1.6.0 - 23.10.2026: research-before-build-проход по приорам (пропущен при создании - признано): импортированы лучшие практики интервью - Mom Test (прошлое и конкретика вместо гипотетики, не питчить во время открытия), JTBD switch interview (таймлайн последнего случая), свой полевой опросник героев (последний случай вместо практики, [ядро], вопрос-контрпример «где он прав», вопрос на цитату), grill-me (ничего молчаливого) и decision-questionnaire (подтверждение хода «витрина вместо неответчного вопроса»). Сводка - references/interview-methods.md.
- v1.6.1 - 23.10.2026: скилл опубликован: публичный репо github.com/NikolayGusev-astra/kto-ty-voin (README с отсылкой к «Трое», MIT) и stateless онлайн-конструктор профиля на GitHub Pages; правки скилла синхронизируются с публичным репо в том же сеансе.
